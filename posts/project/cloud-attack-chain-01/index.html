취약점은 리스트가 아니라 “흐름”이다#

AI 기반 클라우드 공격 체인 분석 시스템을 시작하며#

클라우드 취약점 진단 도구를 실행하면 항상 비슷한 결과가 나온다.

  • Security Group이 0.0.0.0/0으로 열려 있습니다.
  • IAM 권한이 과도합니다.
  • S3 버킷이 공개되어 있습니다.

심각도도 표시되고, HIGH, MEDIUM도 구분되어 있다.

그런데 항상 한 가지가 빠져 있었다.

그래서, 실제로 어디까지 갈 수 있는가?

취약점은 리스트로 제공된다.
하지만 공격은 리스트로 진행되지 않는다.

공격은 연결된다.

이 프로젝트를 시작한 이유#

클라우드 보안을 공부하면서 느낀 가장 큰 답답함은 이것이었다.

취약점은 잘 “탐지”된다.
하지만 취약점이 어떻게 “확장”되는지는 보여주지 않는다.

예를 들어 이런 구조를 생각해보자.

  • Public으로 노출된 ECS 서비스
  • 과도한 IAM Task Role 권한
  • EC2 Instance Role에 AdministratorAccess

ECS (Elastic Container Service)#

AWS에서 Docker 컨테이너를 실행하는 서비스다.
이 프로젝트에서는 공격 대상 애플리케이션이 올라가는 환경이다.

IAM (Identity and Access Management)#

AWS 리소스에 대한 접근 권한을 관리하는 시스템이다.
권한이 과도하면 Privilege Escalation(권한 상승)이 가능해진다.

이 세 가지는 각각 HIGH로 분류될 수 있다.

하지만 연결되면 이런 흐름이 된다.

Public Access
↓
Container Compromise
↓
ECS Task Role 획득
↓
AWS 리소스 접근

이건 단순 HIGH가 아니다.
완전한 침해 시나리오다.

그런데 대부분의 도구는 이 연결을 보여주지 않는다.

그래서 이런 질문이 생겼다.

취약점을 그래프로 연결하면 어떨까?

이 프로젝트의 방향#

이 프로젝트는 단순 취약점 스캐너를 만드는 것이 아니다.

Terraform 기반으로 AWS 인프라를 직접 설계하고,
그 위에서 발견된 취약점을 연결해
공격 체인(Attack Chain)을 모델링하는 시스템을 구현한다.

Terraform#

인프라를 코드로 정의하는 IaC(Infrastructure as Code) 도구다.
이 프로젝트에서는 재현 가능한 인프라 구성과 자동 취약점 분석을 위해 사용한다.

tfsec#

Terraform 코드의 보안 취약점을 분석하는 정적 분석 도구다.
Attack Graph를 생성하기 위한 입력 데이터 역할을 한다.

목표는 명확하다.

“취약점 목록”이 아니라
“공격 흐름”을 계산하는 플랫폼을 만드는 것

왜 AWS를 실제로 사용하는가#

이 프로젝트는 이론적 모델링이 아니다.

  • VPC 설계
  • ECS 배포
  • IAM Role 구성
  • tfsec 실행
  • Attack Graph 생성
  • Risk 계산

모든 과정을 실제 AWS 환경에서 수행한다.

인프라를 이해한 상태에서 보안을 분석한다.

다음 글에서는 네트워크 설계부터 시작한다. 공격 흐름을 계산하려면, 먼저 공격이 시작되는 환경을 정의해야 한다.
