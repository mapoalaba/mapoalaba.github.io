왜 VPC부터 설계했을까?#

공격 체인을 정의하는 첫 단계#

ECS부터 띄우는 게 더 빠를 수도 있었다.
실제로 이전에는 그렇게 해본 적도 있다.

하지만 이번에는 다르게 가고 싶었다.

공격 체인을 분석하려면
공격이 시작되는 지점을 먼저 정의해야 한다고 생각했다.

그래서 가장 먼저 고민한 것은 네트워크였다.

VPC를 직접 설계하기로 한 이유#

VPC (Virtual Private Cloud)#

AWS 안에 만드는 격리된 네트워크 공간이다.
IP 범위(CIDR)를 직접 정의하고, Subnet을 나누고, 경계를 설계할 수 있다.

AWS는 Default VPC를 기본 제공한다.
그걸 그대로 써도 ECS는 잘 올라간다.

하지만 그건 “구성”이지 “설계”는 아니라고 생각했다.

이번 프로젝트는
왜 이렇게 구성했는지 설명할 수 있어야 했다.

그래서 Terraform으로 VPC를 직접 만들기로 했다.

Subnet을 나눈 이유#

Subnet#

VPC 내부를 더 작은 네트워크 단위로 나눈 영역이다.

Public Subnet과 Private Subnet으로 나누는 이유는 단순한 구조 분리가 아니다.

  • Public Subnet → 인터넷에서 직접 접근 가능
  • Private Subnet → 외부에서 직접 접근 불가

이 구분은 곧 공격 표면(Attack Surface)을 정의한다.

공격 체인을 모델링하려면
어디가 노출되어 있고, 어디가 격리되어 있는지
명확해야 한다.

Internet Gateway와 Route Table#

Internet Gateway (IGW)#

VPC가 인터넷과 통신할 수 있도록 연결해주는 리소스다.

Route Table#

네트워크 트래픽이 어디로 향하는지 정의하는 규칙표다.

예를 들어: 0.0.0.0/0 → IGW

이 설정이 있으면 해당 Subnet은 Public이 된다.

이 프로젝트에서는
공격이 시작될 수 있는 경로를 의도적으로 만들기 위해
Public Route를 설정했다.

NAT Gateway를 만들지 않은 이유#

NAT Gateway#

Private Subnet 리소스가 인터넷으로 나갈 수 있도록 해주는 서비스다.

일반적인 운영 환경이라면 구성하는 것이 맞다.

하지만 이번 프로젝트는 공격 체인 분석이 목적이다.

  • 내부 통신이 필수 구조가 아님
  • 비용 증가
  • 분석 목적과 직접적 관련 없음

그래서 NAT은 제외했다.

정리#

네트워크 설계는 단순 인프라 구축이 아니다.

  • 공격 시작점 정의
  • 노출 영역 설정
  • 경계 모델링

Attack Graph의 첫 노드는
네트워크 설계에서 시작된다.

IAM Role과 컨테이너 실행 구조가 공격 체인에 어떻게 연결되는지 정리한다.
